## Decisions worth not relitigating

- **Landing tokens are scoped to `.landing`, not `:root`.** The landing's palette collides *by
  name* with the app's — `--bg`, `--surface`, `--line`, `--text`, `--amber`, `--teal` all exist in
  `tokens.css` with completely different values. Scoping shadows them for that subtree only. The
  signed-in app is untouched and keeps its slate shell.
- **Two type systems on one origin, deliberately.** App = Archivo / Inter Tight / JetBrains Mono.
  Landing = Chivo / IBM Plex Sans / IBM Plex Mono, rebound onto the same three role variables
  inside `.landing`. All self-hosted via `@fontsource`. No CDN fonts, no embed, no trackers.
- **Currency is `$`** (owner call 2026-08-11), against the design's £ default. Read off
  `PRICE_CENTS` in `data/model.ts` so the landing cannot drift from Billing. One constant to flip.
  Both prices always shown separately — $80 manager / $50 technician; the calculator is the only
  place a combined figure appears.
- **Mobile was covered by the design** (fluid `clamp()` + `flex: 1 1 <min>`, no breakpoints), so
  it was implemented rather than guessed at.

### Two documented divergences from the handoff

1. **Quote grid.** The handoff asks for `repeat(auto-fit, minmax(340px,1fr))` *and* for
   "4 → 2 → 1, never 3". Those contradict — at the 1240px column that minimum resolves to exactly
   3 tracks and orphans the fourth quote. Fixed counts at two breakpoints; the only media-query
   grid on the page.
2. **Gap-grid dividers.** The handoff draws them as 1px gaps over a `--line` background. Done
   literally, an unfilled row leaves an empty cell painted `--line` — the blank grey panel the
   handoff itself warns about. Container stays `--surface`; each cell casts a 1px `--line`
   box-shadow instead.

Both are commented at the point they occur in `landing.css`.

## Verification already done — do not redo

```
npm run portal:build && npm run typecheck && npm run lint && npm test
```
All green. 66 test files, 1012 tests.

**Contrast audit** (walk every text node, resolve colour *through a canvas* — `getComputedStyle`
returns `oklch()` and naive parsing gives garbage — first opaque ancestor background, WCAG ratio):

- **122 text nodes, 0 failures. Lowest pair 5.53:1** against a 4.5 requirement.
- Worst-case composites computed separately for the 22 nodes over background-images (blueprint
  grid, amber hatch plates, photo-band gradient).
- Hover, focus, placeholder and the form's confirmation state audited separately — all pass.

**It caught one real fault**, now fixed in `67fbaf7`: `.landing a` scores (0,1,1) and outranked
every single-class component rule, so the amber CTA's label inherited `--text` instead of
`--on-amber` — **2.17:1**. `:where()` drops the reset to (0,1,0). The Sign-in `<button>` also
needed an explicit transparent background or the UA painted near-white `buttonface` under it.

**Responsive**, verified at 390 / 900 / 1440px: no horizontal overflow at any width; quote grid
1 → 2 → 4, never 3; all `auto-fit` empty tracks collapse to 0px with no orphaned cells; nav
collapses to wordmark + Sign in under 520px; steppers exactly 44px; phone order is headline →
lead → buttons → film, pricing stacks technician → manager → calculator.

## Running it

```bash
npm run portal:dev          # hot reload
npm run portal:build        # production build → web/portal/dist
npm run typecheck && npm run lint && npm test && npm run build
```

Serve the real route:
```bash
PORTAL_STATIC_DIR=web/portal/dist MCP_HTTP_PORT=8932 node dist/mcp/httpServer.js
# then http://localhost:8932/portal
```

**Tests need Docker + the local Supabase stack.** If Docker is paused: `docker desktop restart`,
then `npx supabase start`. A fresh stack has no migrations — `npx supabase db reset` (local only;
`testEnvGuard` protects the pilot DB). The stack was left **running** at the end of this session.
